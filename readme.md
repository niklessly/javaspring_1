# ДЗ: Консольный калькулятор на Spring (IoC/DI + 3 вида конфигурации)

## Цель
Разработать консольное приложение-калькулятор, которое:
- выполняет арифметические операции **с двумя числами**,
- вычисляет **факториал**,
- использует паттерн **Strategy** для операций,
- использует Spring Context и **совмещает 3 вида конфигурации**: **XML + Java Config + Annotation Config**.

---

## Функциональные требования

### 1) Операции
Поддержать минимум:
- `+` — сложение (2 числа)
- `-` — вычитание (2 числа)
- `*` — умножение (2 числа)
- `/` — деление (2 числа)
- `!` — факториал (1 число)

Доп. операции можно добавлять по желанию (необязательно).

---

### 2) Консольный интерфейс
Приложение работает в цикле:
- выводит список доступных операций/подсказку,
- читает команду операции (`+`, `-`, `*`, `/`, `!`),
- читает нужное количество аргументов (для `!` — один аргумент, для остальных — два),
- выводит результат,
- поддерживает выход по команде `exit` (или `0`).

---

### 3) Обработка ошибок (обязательно)
- неизвестная команда → понятное сообщение
- деление на ноль → понятное сообщение
- факториал от отрицательного числа → ошибка
- некорректный ввод числа → ошибка (можно просто вывести сообщение и продолжить цикл)

---

## Архитектурные требования

### 4) Strategy
Операции реализовать через паттерн **Strategy**:
- общий интерфейс стратегии (например `Operation`),
- отдельные реализации под каждую операцию (`AddOperation`, `DivideOperation`, `FactorialOperation`, ...),
- выбор стратегии по введённой команде.

Рекомендуемая идея интерфейса:
- `String key()` — ключ операции (`"+"`, `"-"`, `"!"`)
- `int arity()` — сколько аргументов нужно (1 или 2)
- `double apply(double a, double b)` / `double apply(double a)` — вычисление

(Точная сигнатура — на ваше усмотрение, главное: Strategy и подмена реализаций.)

---

### 5) IO как сервис (обязательно)
Ввод/вывод вынести в отдельный сервис:
- интерфейс `IoService` (`readLine()`, `print()`, `println()`)
- реализация `ConsoleIoService` (через `Scanner` или `BufferedReader`)

**Важно:** бизнес-логика не должна напрямую использовать `System.out` и `Scanner`.

---

### 6) Навигатор стратегий (обязательно)
Сделать навигатор/реестр стратегий, например `OperationNavigator`, который:
- хранит доступные операции,
- умеет получить стратегию по ключу (`"+"`, `"!"`),
- может вернуть список доступных операций (для меню/подсказки).

---

## Требования к конфигурации Spring (обязательно)

Нужно совместить **все три** вида конфигурации в одном приложении.

### A) XML-конфигурация — для навигатора стратегий
- `OperationNavigator` должен быть **создан через XML**.
- В XML должен быть показан wiring стратегий (например через `List<Operation>` или `Map<String, Operation>`).
- XML должен лежать в `resources` (например `application-context.xml`).

### B) Java Config — для сервиса ввода-вывода
- `IoService` / `ConsoleIoService` объявить через `@Configuration + @Bean`.

### C) Annotation Config — для стратегий операций
- Стратегии операций объявить через аннотации `@Component` (или `@Service`).
- Подключить `@ComponentScan`, чтобы Spring их нашёл.

### Остальное
Остальные классы (runner/controller/app) — по необходимости/по желанию:
- можно через `@Component`,
- можно через `@Bean`,
- можно через XML (не обязательно).

---

## Запуск приложения
- Должен быть `main()`, который поднимает Spring Context и запускает цикл калькулятора.
- Способ поднятия контекста — на ваш выбор, но в проекте должны реально использоваться:
  - XML (навигатор),
  - Java Config (IO),
  - Annotation Config (стратегии).

---

## Критерии приёмки (чеклист)
- [ ] Работают `+`, `-`, `*`, `/`, `!`
- [ ] Обрабатываются ошибки (деление на ноль, отрицательный факториал, неверный ввод)
- [ ] Strategy реализован: операции — отдельные классы с общим интерфейсом
- [ ] IO вынесен в `IoService` и создан через Java Config
- [ ] Навигатор стратегий создан через XML и получает стратегии через ссылки на бины
- [ ] Стратегии созданы через аннотации и подхватываются `@ComponentScan`
- [ ] Есть `main()` и приложение работает до команды выхода
